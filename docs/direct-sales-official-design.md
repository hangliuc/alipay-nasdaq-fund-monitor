# 直销限额获取方案（仅基金公司一手来源）

## 边界

- 禁止使用东方财富、天天基金、支付宝、雪球、AKShare 等第三方数据作为直销额度来源。
- 仅允许基金管理人自有域名上的官网、官方 App/小程序公开接口、官网披露公告和已授权查询 API。
- 现有第三方限额卡片不修改。

## 单条数据结构

每条直销结果必须包含：基金公司、基金代码、额度或暂停状态、渠道类型、官方 URL/API、抓取时间、是否明确直销、认证状态。

## Adapter 流程

1. 官网公开产品页或公开交易状态 API。
2. 基金公司官网限额表或官网信息披露公告。
3. 未登录 App/小程序公开接口。
4. 已授权查询 API（令牌只从环境变量读取）。

当前实现还包括两类可复用探测：

- 产品页内嵌 JSON/脚本：例如华泰柏瑞官网 `FundArr.limitmoney`，不需要浏览器登录即可解析。
- 官网临时公告分页 → 最新公告 PDF：例如广发官网公告列表，遍历分页后按基金代码和 A/C 类标题定位 006479、021277 的业务限额。
- 广发官网产品页 `fund-person-limit.shtml`/`fund-org-limit.shtml`：由产品页脚本直接调用，个人 `MAX_ALLOT_BALA` 作为当前直销个人上限，机构值仅作审计字段；个人接口无上限时，再由**广发自己的 Adapter**继续查询官网公告 PDF（仍属于同一公司 Adapter，不是统一兼容层回填）。
- 官网产品页信息披露加载接口 → 最新公告 PDF：例如国富 `/qxjj/jjxq/xxplload`，读取 021662、021842 的最新公告；若公告明确直销/非直销，优先取直销金额。
- 官网产品页当前交易状态：例如博时产品页在基金代码旁直接公开“暂停申购”，可记录为交易状态，不把起投金额误当限额。
- 官网公告 PDF：例如华宝 008254、017204、017437 的直销柜台/网上直销限额；接口临时要求网点代码时不绕过，只有本次成功读取并解析的官方 PDF 才能写入 Adapter 结果。
- 产品页公告列表 → 最新公告 → 官方 PDF：例如富国官网自动选择最新“暂停大额申购及定投”公告，并按份额代码对齐金额。
- 官网公告 API → 公开 DOC 附件：例如建信 `/website/v1/api/fund/notice`，详情页附件由系统转换文本后按基金代码解析；附件内明确的“直销渠道”例外优先于通用限额。
- 官网产品页公告 → 官方 PDF：例如长城产品页临时公告及限额公告，按份额代码解析当前限额；下载触发官网频率限制时本次保持“未获取”并自动重试，不保留历史值、不从第三方补值。
- 官网产品页公告直链 → 官方 CDN PDF：例如天弘产品页公告附件，解析 016665 的直销 1,000 元和 018044 的暂停状态；产品页遇到 WAF 时不绕过，只读取页面已公开的官方附件。
- 官网直销系统匿名 session → 公开基金详情 API：例如宝盈 `ibao.byfunds.com/agate/api/v1/fund/detail`，按其前端公开的 `_sign`、session/token 和 `td_sum_max_20/22` 字段读取 019737 的 10 元申购上限；仅限无需账号即可返回的字段。
- 官网统一直销登录入口：例如银华统一交易登录页，未登录即进入认证边界，记录“官方接口需认证”；浦银安盛已接入官网公开目录、产品和公告接口，公开公告可验证时直接写入当前状态。

交易入口只做 GET 探测和认证边界识别。出现登录、验证码、设备签名或银行卡绑定时，结果写为“官方接口需认证”，不提交订单、不绕过校验。

如果上述渠道都不能得到数据，记录为“未获取”；不作推断，不用第三方值填充。

## 认证令牌

发现某家公司确有稳定的已认证查询 API 后，单独指定环境变量名称。令牌不会写入 `config.json`、代码、报告或 Git；不采集密码、验证码、身份证或银行卡信息。

## 代码结构

`fund_monitor/fetch/direct_sales_official.py` 现在只是兼容入口，实际逻辑按职责拆分在 `fund_monitor/fetch/direct_sales/`：

- `registry.py`：24 家管理人注册表、官方域名、公告入口和覆盖审计。
- `common.py`：金额标准化、结果记录、PDF/DOC/DOCX 文本提取。
- `product_pages.py`：产品页、目录脚本和公开状态 API Adapter。
- `announcements.py`：官网公告列表、PDF/DOC 附件及各公司独立 Adapter 的公告解析入口；不承担统一静态值回填。
- `trade_api.py`：无需登录即可返回数据的官方交易 API Adapter。
- `boundaries.py`：公告入口追踪、登录/验证码/会话认证边界探测。
- `orchestrator.py`：统一按优先级编排所有 Adapter，保证专用结果不会被通用探测覆盖。

新增基金公司时，优先在对应职责模块增加独立函数，并在 `orchestrator.py` 注册调用；旧的导入路径无需修改。

## 生产写入规则（所有 Adapter 统一）

1. 只有对应公司独立 Adapter 在本次运行从该公司官方公开页面/API/公告解析出的明确当前限额或暂停/恢复状态，才写入“已获取直销”。
2. `official_api_no_data`、`official_interface_requires_auth`、HTTP 限制、网络失败或字段无法确认，均写入“未获取/需认证”；不以历史值、统一静态映射、第三方平台或另一家公司 Adapter 的结果替代。
3. 统一编排只负责调用和汇总，不改变 Adapter 的状态，也不提供数据兜底。这样可以避免旧值掩盖万家、景顺长城等当前无法验证的结果。
