# 基金公司全基金独立 Adapter 统计与实施报告

## 1. 目标重新定义

本项目下一阶段不再只服务 `config.json` 中的基金，而是为每一家基金管理人建立一个独立 Adapter，自动发现该公司官网公开的全部基金，并获取每只基金的产品信息、交易状态和直销限额。

目标数据范围：

- 公司官网公开的全部公募基金及份额类别，不限于 QDII 或当前关注清单；
- 基金代码、基金名称、份额类别、基金类型、币种、风险等级；
- 认购、申购、赎回、定投、转换转入/转出状态；
- 直销渠道申购限额、代销渠道限额（若官网明确区分）；
- 公告生效日期、数据观察时间、来源 URL、来源类型和认证边界；
- 未获取、需认证、页面存在但无字段、网络失败等可审计状态。

## 2. 当前基线统计

- `config.json`：37 只基金；
- 已匹配基金管理人：24 家；
- 当前代码已有管理人注册表；24 家管理人均已有独立 Adapter，最近新增浦银安盛、银华两家；每家均有独立官网目录/产品/公告或认证边界逻辑；
- 已验证实时交易 API：2 家、4 只基金（易方达、宝盈）；
- 已验证官网当前产品页/状态页：7 家、10 只基金（国泰、华安、华夏、国富、富国、博时、南方）；
- 已新增南方独立 Adapter：官网 `fundList`、`overreview` 和交易状态 API 均可匿名访问，当前目录合并发现 975 只基金；配置基金 016453 已获取 10 元限额；
- 其他 11 家、14 只基金目前主要依赖公告 PDF、限额表或公开目录脚本；
- 当前实现尚未达到“每家公司一个完全独立 Adapter、自动发现该公司全部基金”的目标。

## 3. 每家公司独立 Adapter 就绪度

状态含义：

- **P1：公开入口明确**：已有公开 API、产品页或状态页，可优先做全量目录发现；
- **P2：公开公告/目录可用**：已有官方来源，但需要先建立基金目录，再组合产品页与公告解析；

## 4. 适配器统一契约

每家公司单独一个模块，例如：

```text
fund_monitor/fetch/direct_sales/adapters/
├── base.py
├── e_funds.py
├── baoying.py
├── china_amc.py
├── guotai.py
├── huaan.py
├── ...
└── registry.py
```

每个 Adapter 只负责自己的官网规则，不能把一家公司的字段规则写进另一家公司的通用正则。统一实现以下接口：

```python
class ManagerAdapter:
    manager_id: str

    def discover_funds(self) -> list[FundIdentity]: ...
    def fetch_product(self, fund: FundIdentity) -> ProductSnapshot: ...
    def fetch_trade_status(self, fund: FundIdentity) -> TradeSnapshot: ...
    def fetch_direct_limit(self, fund: FundIdentity) -> LimitSnapshot: ...
    def fetch_announcements(self, fund: FundIdentity) -> list[Announcement]: ...
    def auth_boundary(self) -> AuthBoundary: ...
```

每条结果必须带：

```text
manager_id
fund_code
share_class
name
source_type
source_url
observed_at
effective_at（若公告有生效日期）
status
direct_limit
distribution_limit
auth_status
raw_payload_hash
```

## 5. 全基金发现与交易数据必须分层

不能把“发现到基金代码”误当成“拿到了当前交易状态”。每家公司 Adapter 分三层：

1. **Universe 层**：从官网基金超市、基金列表、产品搜索、公开 JSON/JS 目录发现全部基金；保存代码、名称、份额类别和页面 URL。
2. **Product 层**：读取单只基金产品页，解析当前交易状态、直销/代销限额和页面更新时间。
3. **Notice/API 层**：读取实时交易 API 或最新公告，解析生效日期、限额、暂停/恢复规则；仅在本次运行成功解析时写入结果。

优先级建议：

```text
当前交易 API > 当前产品页交易状态 > 当前状态表 > 最新生效公告 > 未获取
```

如果 API 返回空数据、页面没有基金行、会话过期或字段无法确认，必须记录为“未获取/需认证”；统一编排不得用历史核验值、静态映射或第三方数据回填。

## 6. 全基金覆盖率指标

以后报告不再只统计 `config.json` 命中率，改为每家公司统计：

| 指标 | 含义 |
|---|---|
| `universe_discovered` | 官网发现的基金总数 |
| `universe_deduplicated` | 去除同代码重复记录后的基金数 |
| `product_page_ok` | 可访问并解析产品页的基金数 |
| `trade_status_ok` | 获取当前申购/赎回/定投状态的基金数 |
| `direct_limit_ok` | 获取直销限额的基金数 |
| `auth_required` | 需要登录、验证码、设备签名或银行卡绑定的基金数 |
| `source_stale` | 只有历史公告/历史核验值的基金数 |
| `unknown` | 入口存在但当前没有可验证字段的基金数 |

关键覆盖率：

```text
产品覆盖率 = product_page_ok / universe_discovered
交易状态覆盖率 = trade_status_ok / universe_discovered
直销限额覆盖率 = direct_limit_ok / universe_discovered
```

## 7. 推荐攻克顺序

### 第一批：先建立公开全量目录和实时状态

易方达、宝盈、国泰、华安、华夏、国富、博时、南方、华泰柏瑞。

这些公司已有 API、产品页、公开目录脚本或状态页证据，最适合先做成可开源的完整 Adapter 样板。

### 第二批：产品目录 + 公告联动

24 家管理人均已完成独立 Adapter 模块；浦银安盛已能获取配置基金的当前状态，银华仍保留认证/未获取状态。

这批公司应先做到“官网全基金发现”，再将最新公告按基金代码和份额类别关联；公告不能被标成实时 API。

### 第三批：认证边界和入口研究

银华，以及广发、博时、宝盈、华宝等公司的认证交易入口仍需遵循认证边界；不因 Adapter 已存在而猜测直销限额。

只有在确认官网公开接口确实要求认证后，才考虑接入用户授权 Token。认证链路必须支持失效、撤销和权限不足，不允许自动尝试绕过验证码、设备签名或银行卡绑定。

## 8. 关于账号、开户和 Token

当前阶段**不需要提供账号、密码、验证码或银行卡信息**。先完成所有公开页面、公开 API、公开基金目录和公告链路。

只有当某家公司满足以下条件时，才需要用户授权信息：

- 官网确实存在基金详情/交易状态接口；
- 未登录响应明确要求认证；
- 该接口允许合法使用授权 Token；
- 可以使用短期 Token 或只读会话，而不是保存密码。

届时只接受通过环境变量或运行时注入的短期 Token，不写入代码、`config.json`、报告或 Git；运行日志中也不得输出完整 Token。若没有授权 Token，该基金应保持 `official_interface_requires_auth`，不影响其他公司的 Adapter 运行。

## 9. 开源发布要求

每个 Adapter 发布前必须具备：

- 独立模块、独立 README 和官方来源清单；
- 固定 HTML/JSON/PDF fixture，离线单元测试；
- 公网 live probe 与离线测试分离；
- 速率限制、缓存、重试和 `robots.txt`/网站条款审查；
- 不包含账号、密码、Cookie、Token、验证码或银行卡信息；
- 输出原始来源 URL、观察时间、生效时间和解析版本；
- 明确“官方 API”“官方产品页”“官方公告”“需认证”“未获取”的状态枚举。

## 10. 本报告结论

当前项目已经证明：24 家管理人都可以先建立独立 Adapter，但“已有 config 基金结果”与“覆盖该公司全部基金”是两件不同的事。

当前 24 家管理人均已有独立 Adapter。下一步应继续提高各 Adapter 的 Universe、产品页和当前交易状态覆盖率；对银华等需认证公司保持“未获取/需认证”，不使用统一兼容层、历史静态值或第三方数据回填。账号或开户不是启动条件；只有公开链路确认无法完成且官方授权接口允许使用时，才进入 Token 接入阶段。
