# 数据获取流程

## 数据源

项目只保留两类实时数据获取方式：

1. AKShare 接口：批量获取结构化基金数据。
2. 天天基金 HTML 详情页：逐只获取数据，作为备用和交叉验证来源。

AKShare 底层通常仍会调用东方财富或天天基金的公开接口，因此二者不是完全独立的数据供应商。但它们的请求方式、返回格式和失败模式不同，组合使用可以降低单个接口异常的影响。

| 字段 | AKShare | 天天基金 HTML 详情页 |
|---|---|---|
| 申购状态 | `fund_purchase_em` | 支持解析 |
| 限购额度 | `fund_purchase_em` | 支持解析 |
| 最新净值 | `fund_purchase_em` / `fund_open_fund_rank_em` | 页面存在时解析 |
| 净值日期 | `fund_purchase_em` / `fund_open_fund_rank_em` | 页面存在时解析 |
| 近一年收益率 | `fund_open_fund_rank_em` | 支持解析 |
| 国家/地区市场分布 | 不负责 | 不负责 |

市场分布是可选功能，单独查询证监会季度报告，不参与基金限购和收益率的主备切换。

## 固定运行策略

每次运行都采用同一种流程：

```text
1. AKShare 批量查询全市场数据
2. 逐只请求目标基金的天天基金 HTML 详情页
3. 合并结果并进行字段级交叉验证
4. 一方失败时使用另一方结果
5. 两方都失败时使用 history.json
6. 生成日报、记录历史并发送通知
```

HTML 请求逐只执行，并在请求之间保留延迟；不再维护多套运行模式。

## 交叉验证字段

当 AKShare 和天天基金 HTML 详情页都成功时，当前程序会对以下共同字段进行交叉验证：

| 字段 | 比对方式 | 不一致处理 |
|---|---|---|
| 申购状态 | 比较状态类别，兼容同类表述 | 保留 AKShare 值，增加告警，置信度降为 `medium` |
| 限购额度 | 统一换算为元后比较；开放或暂停状态不比较无意义额度 | 保留 AKShare 值，增加告警，置信度降为 `medium` |
| 近一年收益率 | 统一转换为数值，允许不超过 `0.05` 个百分点的误差 | 保留 AKShare 值，增加告警，置信度降为 `medium` |

以下字段目前由 AKShare 提供，但天天基金 HTML 解析器尚未稳定解析，因此暂不作为自动交叉验证条件：

- 最新净值；
- 净值日期；
- 基金名称（只用于匹配和展示，不作为数据质量判断依据）。

如果未来 HTML 解析器补充了净值和净值日期，应再增加数值误差、日期一致性和数据新鲜度校验。交叉验证只在两个来源都提供同一字段时执行，不会因为某个来源缺少非必需字段而判定为不一致。

## 合并规则

### 两个来源都成功

优先使用 AKShare 的结构化结果，同时比较申购状态、限购额度和近一年收益率。比较前先标准化金额、百分比和空值。

结果一致时标记为 `high`；存在差异时保留 AKShare 结果，增加告警，置信度降为 `medium`。

暂停申购基金可能不会出现在 AKShare 的排行结果中，因此其近一年收益率由天天基金 HTML 详情页提供。只要限购数据来自 AKShare、HTML 状态与限购信息验证一致，且没有字段冲突，这属于预期的数据覆盖差异，整体仍标记为 `high`，不因 `performance_source=html` 单独降级。

### 只有一个来源成功

- AKShare 成功、HTML 失败：使用 AKShare，并记录 HTML 失败原因。
- AKShare 失败、HTML 成功：使用 HTML，置信度标记为 `medium`，并提示发生回落。

### 两个来源都失败

如果 `history.json` 存在最近成功快照，则使用历史值并标记：

```text
source = stale
confidence = low
```

如果没有历史值，则返回失败记录，不把未知数据伪装成正常结果。

## AKShare 接口

当前使用：

```python
ak.fund_purchase_em()
ak.fund_open_fund_rank_em()
```

调用后必须检查异常、空表、必需列、基金代码匹配、数据日期和数值范围。不能只根据 HTTP `200` 判断成功，因为接口可能返回业务错误信息或空数据。

## 天天基金 HTML 详情页

天天基金 HTML 详情页按基金代码逐只访问。解析器必须检查 HTTP 状态码、页面类型和必需字段，并记录解析失败、页面改版、验证码或反爬响应。所有请求都要设置超时并限速。

HTML 属于页面展示层，结构可能变化，因此即使解析成功，也要通过交叉验证和数据合理性检查后再确定置信度。

## 数据质量与告警

每条结果保留：

- `source`：当前主要值的来源；
- `confidence`：`high`、`medium` 或 `low`；
- `warnings`：来源切换、字段不一致、数据陈旧等提醒；
- `error`：来源最终失败时的错误信息。

应对以下情况发出告警：AKShare 返回空表或缺少必需列、返回业务错误码、HTML 返回验证码或拦截页、两个来源的状态或限额不一致、净值日期过旧，以及使用历史快照作为最终结果。

## 限制

- AKShare 与 HTML 可能共享底层数据平台，因此交叉验证不等同于独立供应商验证。
- HTML 逐只请求会增加运行时间，必须保留请求间隔。
- 外部接口和网页结构都可能变化，应使用 fixture 保存典型响应并持续做回归测试。
- 任何来源都不保证绝对正确，通知中应保留来源和健康度信息。
